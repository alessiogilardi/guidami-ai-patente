# Patterns and Conventions

Enforceable rules (typing, DI ordering, config-loading, import style) live
in `~/.claude/rules/python/` and `.claude/rules/`. This file only records
recurring idioms actually adopted in the code, as a reference for reuse —
it does not restate those rules.

## Adopted patterns

| Pattern | Where it's used | Why |
|---|---|---|
| `UseCase[T_In, T_Out]` / `AsyncUseCase` protocol | `src/commons/use_cases/use_case.py` — `__call__` is `@final`, delegates to abstract `execute()` | Uniform callable contract for domain logic; every business-logic unit is typed, testable, composable |
| `ForEach[T, U]` | `src/commons/use_cases/for_each.py` — a `UseCase[Iterable[T], list[U]]` wrapping a per-item callable | Turns any `UseCase`/callable into a list-mapper without per-step loop boilerplate |
| `FlatMap[T, U]` | `src/commons/use_cases/flat_map.py` — a `UseCase[Iterable[T], list[U]]` wrapping a per-item `Callable[[T], Iterable[U]]`, concatenating results | One-to-many transforms (one input produces N outputs); e.g. `ApplyStep("chunk_articles", FlatMap(ArticleChunker()), ...)` in `orchestrators/knowledge_flows.py` (source read from each article, not injected — see the per-element layer row below) and `ApplyStep("flatten_quiz", FlatMap(QuizMapper.from_parsed_to_cleaned_all), DeduplicateQuizItems(), ...)` in `orchestrators/quiz_flows.py` |
| `ApplyStep(ForEach(...))` composition | `orchestrators/knowledge_flows.py` — e.g. `ApplyStep("map_to_chunk_entity", ForEach(ArticleMapper.from_embeddable_chunk_to_knowledge_chunk), ...)` and `ApplyStep("map_cleaned_articles", ForEach(ArticleMapper.from_cleaned_to_enriched), ...)` (the sync base-map feeding the async enrichment step) | Standard glue between the domain-agnostic `flowstep` framework (external git dependency, see `docs/architecture.md`) and per-item domain transforms/mappers |
| `Iterable[T]`-typed `ApplyStep` transforms | All `UseCase` subclasses passed as `ApplyStep(...)` transforms (`ForEach`, `FlatMap`, `DeduplicateQuizItems`, `EmbedQuizMetadata`, `ImageDescriptionEnricher`, `NormReferenceEnricher`, `ContextEnricher`) declare `execute(self, request: Iterable[T]) -> list[U]` | `flowstep`'s `ApplyStep` (external dependency) types transforms as `Callable[[Iterable[Any]], Iterable[Any]]`; a `list[T]`-only parameter fails pyright. Transforms that traverse `request` more than once materialize it first (`request = list(request)`) since `Iterable` doesn't guarantee re-iterability |
| Dedup-before-LLM enricher via `deduplicate` | `services/quiz/enrichers/norm_reference_enricher.py` — build a `dict[key, response]` by mapping `commons.utils.deduplicate(items, key=_make_key)` through the agent, then broadcast each response to every row sharing the key | One LLM call per unique key instead of per row; the order-preserving `deduplicate` pass replaces manual `seen`-set bookkeeping |
| Per-item enricher with concurrent LLM calls | `services/knowledge/enrichers/context_enricher.py` — an `AsyncUseCase`: `execute` materializes the input, builds an `asyncio.Semaphore(max_concurrency)` per run, and fires one `_contextualize` coroutine per article under `asyncio.gather`; each awaits `self._agent.run(...)` inside the semaphore. The `repealed`/empty-`paragraphs` guard short-circuits without a call; per-article failures degrade (article returned unchanged, logged) without aborting the batch. Wired as `AsyncApplyStep("enrich_articles", ContextEnricher(article_contextualizer_concurrency, agent), ...)` in `orchestrators/knowledge_flows.py` | Symmetric to the quiz enrichers (`NormReferenceEnricher`, `ImageDescriptionEnricher`): all knowledge/quiz LLM enrichment now runs concurrently under an `AsyncApplyStep`-owned `asyncio.run`, with the semaphore built per run (never stored on `self`, since it binds to the loop of first use). Unlike the norm/image enrichers, no dedup/grouping — the per-article context is unique, so it's a straight per-item gather |
| Group-by-resource enricher with concurrent LLM calls | `services/quiz/enrichers/image_description_enricher.py` — `_group_by_image` (sync `defaultdict(list)`, keyed on the image filename only) → `_fetch_descriptions` (async: builds every `RoadSignDescriberRequest` first via `RoadSignDescriberMapper.from_enriched_quizzes_to_request` — one per image, concatenating every quiz's context — then fires `_describe_image` calls with `asyncio.gather` under an `asyncio.Semaphore(max_concurrency)` created per run) → `_enrich_quiz` (sync, broadcasts each response to every quiz sharing that image). `execute` stays sync and drives the async part with `asyncio.run(...)` | One vision call per **image**, not per `(image, topic, text)` triple — the describer is answer-blind and already treats quiz text as weak context, so per-triple specialization only bought divergent/costlier calls. The semaphore is built fresh per `_fetch_descriptions` call (never stored on `self`) because an `asyncio.Semaphore` binds to the event loop of its first use, and `execute`'s `asyncio.run` spins a fresh loop every call — storing it would break re-use across runs. Per-image failures degrade (`None`, logged) without aborting the batch |
| `embedded_text` computed property | `models/knowledge/embeddable_chunk.py`; on the quiz side it lives on `models/quiz/quiz_metadata.py:QuizMetadata` directly — `EmbeddedQuizModel` no longer needs it, since `EmbedQuizMetadata` embeds `quiz_metadata` (itself `Embeddable`) rather than the wrapping model | Single source of truth for "what text gets embedded", decoupled from the persisted entity's fields |
| Structured field + `@computed_field` render/translate | `agents/dto/road_sign_describer/road_sign_describer_request.py` — `contexts: list[QuizContextModel]` (`QuizContextModel`: `topic: str`, `texts: list[str]`) stays the structured DTO field, one entry per distinct topic; `contexts_block` (`@computed_field @property`) renders it into an `Argomento: <topic>\nDomande:\n- <text>` block per topic (blocks joined by a blank line) that the prompt template substitutes. `agents/dto/norm_reference_describer/norm_reference_describer_request.py` — `correct_answer: bool` stays typed; `correct_answer_it` (`@computed_field @property`) renders it as the Italian `"Vero"`/`"Falso"` literal the prompt template substitutes. `agents/dto/article_contextualizer/article_contextualizer_request.py` — `paragraphs: list[str]` stays the raw comma list; `paragraphs_block` (`@computed_field @property`) renders it as a numbered `"1. ...\n2. ..."` string the prompt template substitutes (moved out of `ArticleContextualizerMapper`, which now passes `article.paragraphs` through unchanged) | `PromptRenderer` does `model_dump()` + `Template.safe_substitute`, and `model_dump()` includes computed fields — so the template references the derived field (`$contexts_block`, `$correct_answer_it`, `$paragraphs_block`) while the request DTO itself keeps the structured/typed field, never a pre-rendered prompt string. Confirmed repeated pattern (three independent DTOs) for any request field needing a prompt-specific rendering (list → text block, bool → Italian literal, etc.). `RoadSignDescriberMapper._from_enriched_quizzes_to_quiz_context` groups deduplicated `(topic, text)` pairs into one `QuizContextModel` per topic so multiple quiz texts under the same topic render as one `Domande:` bullet list instead of repeating the topic heading; it also deduplicates quiz text globally across topics (a `seen_texts: set[str]`, first-seen topic wins) so a literal text repeated under a different topic isn't rendered twice |
| `embed_repealed` config flag | `configs/ingestor_config.py` (default `False`), consumed by `orchestrators/steps/knowledge/embed_chunks_step.py` | Lets repealed norms be indexed or excluded without a schema/pipeline change |
| Per-element layer I/O + element-derived stable id | `commons/utils/element_id.py` (`element_id(*parts) -> str`, a `uuid5` over a fixed, non-configurable namespace) + `orchestrators/steps/generic/{load_json_dir_step,filter_already_done_step,write_json_dir_step}.py` + `LayerResolver.dir(layer, source)` (container directory, stops before `SourceConfig.file`) + `repositories/file_repository/_base_file_repository.py::load_all(dir)` + `clients/file_system/*::list_files` | Knowledge's `cleaned`/`enriched` layers are one-JSON-file-per-article, keyed by `element_id(article.source, article.number)` (`orchestrators/knowledge_flows.py::_article_id`) instead of one monolithic file per source — see `docs/plans/2026-07-17--per-element-knowledge-layers.md`. `FilterAlreadyDoneStep` (parametrized by an injected `id_of: Callable[[T], str]` keyer, not a domain-aware class) drops elements whose destination file already exists, giving cross-run resumability (`--force` bypasses it) without any write-through/async rework — that is deferred to a follow-up plan. All three steps are domain-agnostic, mirroring `LoadJsonStep`/`WriteJsonStep`'s existing split for monolithic layers; granularity (monolithic vs per-element) is decided by which steps a flow's builder wires in, not by a config flag — `quiz` stays on `LoadJsonStep`/`WriteJsonStep` |
| `BaseAgent[T_In, T_Out]` + `PromptRenderer` | `src/commons/ai/agents/base_agent.py` (wraps `pydantic_ai.Agent`, `from_yaml` factory returning `Self`, `run`/`run_sync`/`__call__`); concrete agents declare `output_type` as a class attribute (e.g. `output_type = RoadSignDescriberResponse`) and inherit `from_yaml` unchanged — no override, no `# type: ignore` | Shared LLM plumbing (config load, prompt rendering, retries); per-agent code reduces to the generic params, the `output_type` attribute, and a prompt file |
| Repository with scoped reset (`*StoreRepository`) | `repositories/db/knowledge_chunk_store_repository.py` extends `BulkInsertStoreRepository[KnowledgeChunk]`, adds `delete_source` alongside the inherited `truncate` | Two reset strategies for two different CLI flows: `ingest index` (per-source reload) vs `ingest reset` (full wipe) |
| Static, verbose mapper methods (`from_X_to_Y`) | `mappers/article_mapper.py`, `mappers/quiz_mapper.py` — all methods static and pure, one pure function per pipeline-stage transform | Confirmed convention: mappers are static utility classes, never DI-injected (see also `feedback_mappers_static_verbose` memory). When a mapper class has only **one** method, the generic `from_model_to_entity` name is used instead of naming the concrete types (e.g. `commons/ai/observability/mappers/llm_call_log_mapper.py`) — no ambiguity to resolve with a single method; multi-method mappers (`ArticleMapper`, `QuizMapper`) keep the specific `from_X_to_Y` style to disambiguate between methods |
| Entity = insertable row projection | `domain/entities/knowledge/knowledge_chunk.py`, `domain/entities/quiz/quiz_question.py` — DB-generated columns (`id`, `created_at`) have **no** field on the entity; `QuizQuestion`'s docstring states the omission | Rule (with rationale) in `.claude/rules/code-conventions.md`, "Entities — insertable projection of the table row" — not restated here. Entities are persistence DTOs by design; rich DDD entities deferred until the FastAPI app brings real invariants |
| Italian prompt-facing text on agent response DTOs | Every `agents/dto/*/*_response.py` (`NormReferenceDescriberResponse`, `ArticleContextualizerResponse`, `RoadSignDescriberResponse`) — class docstring + every `Field(description=...)` are in Italian; an inline note on each class explains why | Rule (with rationale) in `.claude/rules/code-conventions.md`, "Exception — prompt-facing text on agent response DTOs" — not restated here. `pydantic_ai.Agent(output_type=...)` ships this text to the LLM as the JSON schema, so it's prompt content, not code documentation; request DTOs (`*_request.py`) stay English since their docstrings are never shipped as schema |
| Config loaded once at entry point | `cli/main.py` — `IngestorConfig()` constructed inside `main()`, then passed down into every `build_*_flow(config=..., ...)` call | Matches the global rule: root config loaded in `main`, never inside builders/services |
| `OpenRouterProvider` built lazily, only for the command that needs it | `cli/wiring.py:build_open_router_provider` builds `OpenRouterProvider(api_key=config.open_router_config.api_key.get_secret_value())`, called from `cli/main.py` only in the `prepare` branch, and passed into `run_prepare`/`dispatch_prepare` → `build_knowledge_enrichment_flow`/`build_quiz_enrichment_flow` (`open_router_provider: OpenRouterProvider`, required, no default) → each agent's `from_yaml(..., provider, ...)` → `BaseAgent.__init__`, which wraps `OpenRouterModel(model_name, provider=provider)`. `build_*_cleaning_flow`/`build_*_indexing_flow` never take the param — they call no agent | Dependency injection over global state: `pydantic_ai.providers.openrouter.OpenRouterProvider` would otherwise silently read `OPENROUTER_API_KEY` from `os.environ` itself; routing the key through `IngestorConfig.open_router_config` (`commons.configs.OpenRouterConfig`, a `BaseSettings` with `env_prefix="OPENROUTER_"`, built via `Field(default_factory=OpenRouterConfig)` so the env read happens at `IngestorConfig()` construction, not at module-import time) keeps the single root config as the one place secrets are read from. Building it lazily (not eagerly for every command) means `reset`/`status` run without `OPENROUTER_API_KEY` set |
| `AgentConfig.name` optional, agent identity inherited from config | `commons/ai/agents/configs/agent_config.py` — `name: str \| None = Field(default=None, ...)`; `BaseAgent.__init__` still does `self._name = config.name if config.name is not None else type(self).__name__`. Production YAML files under `configs/agents/` set an explicit `name:` (e.g. `road-sign-describer`); tests that omit it fall back to the concrete subclass name | Keeps a human-readable `LlmCallLog.caller` configurable per-agent-instance in YAML without a separate constructor override — `from_yaml`'s `name` positional arg is only the YAML filename, never the identity |
| Port-injected observability (`LlmCallTracker`) | `commons/ai/observability/protocols/llm_call_tracker.py` (`Protocol`, single `track(log)` method) injected into `BaseAgent.__init__`/`from_yaml` as `tracker: LlmCallTracker \| None = None`; `BaseAgent.__init__` normalizes a `None` argument to `NullLlmCallTracker()` (see the Null Object row below), so `self._tracker` is never `Optional` and `run`/`run_sync` always take the same tracked code path | Token usage (`result.usage`, a property as of pydantic_ai 1.107 — the deprecated `result.usage()` method call was fixed while touching this code) only exists inside `BaseAgent.run`/`run_sync`; an external wrapper would force a breaking return-type change. ISP: call sites see only `track()`; lifecycle (`close`) lives on the concrete `QueuedLlmCallTracker`, owned by the composition root (`cli/commands/prepare.py:run_prepare`, via `cli/wiring.py:build_tracker`) |
| Degrade-gracefully exception to fail-explicit | `commons/ai/observability/services/queued_llm_call_tracker.py::_persist` catches bare `Exception` around `repository.insert`, logs `logger.warning(..., exc_info=True)`, and continues; `cli/commands/prepare.py:run_prepare` catches `psycopg.Error` around `wiring.build_postgres_client(...)` and dispatches with `tracker=None` | Observability must never break the main ingestion flow — a documented, narrow exception to "never swallow exceptions" (`.claude/rules/python/standards.md`) |
| Private `protocols/` nested inside `services/` for a narrow dependency | `commons/ai/observability/services/protocols/` — `_LlmCallLogRepository` `Protocol`, typing `QueuedLlmCallTracker`'s ctor param, satisfied structurally by both the real `LlmCallLogRepository` and test doubles with no common base class. Deliberately **not** in the package's top-level `protocols/` (reserved for genuine cross-package ports like `LlmCallTracker`) and not re-exported by any `__init__.py`. Used to hold a second protocol, `_CostCalculator` (for the now-removed `LlmCostCalculator` — see `adr/0004-openrouter-native-cost-tracking.md`); the pattern (private structural protocol per narrow ctor dependency) still applies whenever `QueuedLlmCallTracker` or a sibling gains another swappable collaborator | Lets `QueuedLlmCallTracker.__init__` accept fakes in tests without nominal inheritance, same ISP rationale as `StoreRepository`/`FileRepository` protocols elsewhere — while keeping the package's public surface limited to ports something outside the package actually depends on |
| DTO + object-to-object mapper (`models/` + `mappers/`) | `commons/ai/observability/models/llm_call_capture_model.py` (`LlmCallCaptureModel`, a pydantic `BaseModel` holding one call's captured fields) and `mappers/llm_call_log_mapper.py` (`LlmCallLogMapper.from_model_to_entity(data: LlmCallCaptureModel) -> LlmCallLog`, a real object-to-object transform, not a field-projection helper); `PydanticAILlmCallCapture` builds the DTO internally (`_to_capture_data`) and its `log` property just calls the mapper | Concrete application of the existing "intermediate model + mapper, never extra fields on the entity" rule (`.claude/rules/code-conventions.md`, entities section). A mapper taking a spread of loose primitive params isn't a real mapping — it needs two named shapes on either side to be worth the abstraction |
| Provider-coupled capture named after its provider (`PydanticAILlmCallCapture`) | `commons/ai/observability/services/pydantic_ai_llm_call_capture.py` — `record(result: AgentRunResult[Any])` takes pydantic_ai's own result object directly (not separately-extracted response text + `RunUsage`), since the class already imports pydantic_ai types and the extra unpacking step at the call site (`base_agent.py`) added no value | The class name is honest about the coupling it already has; `record`'s signature stops pretending to be provider-agnostic when its only caller, its only import, and its docstring already commit to pydantic_ai |
| `@classmethod @contextmanager` factory composing capture + tracker | `pydantic_ai_llm_call_capture.py::PydanticAILlmCallCapture.tracked(caller, model, prompt, system_prompt, tracker)` — builds a fresh capture, yields it, tracks `capture.log` in `finally` | The `try: with capture: ... finally: tracker.track(...)` shape was pure boilerplate, not agent-call logic, and `BaseAgent` shouldn't own it — `tracked` lives next to the class it composes. The core class (ctor/`__enter__`/`__exit__`/`record`/`log`) stays tracker-agnostic; only `tracked` knows about `LlmCallTracker`. `capture` is built fresh per call, never in `__init__`: it is stateful (one stopwatch, one response) and concurrent `run` calls would clobber a shared instance |
| Thin private binder for a per-instance-fixed factory call | `base_agent.py::BaseAgent._tracked(prompt)` — the only argument that varies per call; binds `self._name`/`self._model_name`/`self._system_prompt`/`self._tracker` (fixed for the agent's lifetime) and forwards to `PydanticAILlmCallCapture.tracked`. `run`/`run_sync` reduce to `with self._tracked(_prompt_text(prompt_content)) as capture: ...` | `prompt` must still be known **before** entering the `with` (not deferred to `record()`): the error path never calls `record`, and `LlmCallLog.prompt` is `NOT NULL` — a failed call still needs to log what was asked. No `is not None` assertion is needed: `self._tracker` is normalized to a concrete `LlmCallTracker` (real or `NullLlmCallTracker`) in `__init__` |
| Null Object for an optional collaborator (`NullLlmCallTracker`) | `commons/ai/observability/services/null_llm_call_tracker.py` — a plain concrete class (no inheritance) that structurally satisfies `LlmCallTracker` with a no-op `track(log)`; `BaseAgent.__init__` builds one whenever `tracker=None` is passed, so `self._tracker` is always a real `LlmCallTracker` | Removes the `if self._tracker is None: ... else: with self._tracked(...): ...` branch duplicated in `run`/`run_sync` — every call now takes the single tracked path, and an untracked agent just discards its capture instead of skipping the build. Trade-off accepted: `PydanticAILlmCallCapture`/`LlmCallLog` are always built even when untracked, pure CPU cost, negligible next to LLM network latency |

**Naming discrepancy** (worth knowing, not "wrong"): the global
architecture rule (`~/.claude/rules/python/architecture.md`) calls for
`*Pipeline`/`*PipelineBuilder` classes in `orchestrators/`. In this repo,
`orchestrators/knowledge_flows.py` and `quiz_flows.py` instead use
**factory functions** returning a `flowstep.Flow`
(`build_knowledge_indexing_flow`, `build_quiz_cleaning_flow`, etc.) — the
`flowstep` framework's own vocabulary (`Flow`/`FlowBuilder`) replaces the
`*Pipeline`/`*PipelineBuilder` naming here. Follow this file's precedent
in `orchestrators/`, not the generic rule's literal class names.

`MapStep`, `EnrichDataStep`, and `EnricherProtocol` were removed from the
codebase (per the legacy architecture docs) — confirmed gone from `src/`.
Stale references to them survive only as outdated comments in
`orchestrators/context_keys.py`; don't use them as a model for new code.

## Available, not yet adopted

- `commons/utils/hash_utils.py::HashUtils.make_hashable` and
  `commons/utils/pydantic_utils/` (`PydanticInstanceUtils.group_by`/`filter_by`,
  `PydanticModelUtils.validate_model_attributes`) — a generic "group/filter a
  sequence of Pydantic models by one or more attributes" utility, with a
  validated multi-attribute key and non-hashable-value support via
  `HashUtils.make_hashable`. Fully tested (`tests/commons/utils/`), but **no
  call site uses it yet**: `image_description_enricher.py`'s grouping needs
  were single-attribute and `str`-keyed, so it uses a plain `defaultdict`
  instead (see `adr/0003-group-road-sign-description-by-image.md`). Reach
  for `PydanticInstanceUtils.group_by`/`filter_by` when a real caller needs
  multi-attribute or non-hashable-value grouping; don't add a second,
  parallel grouping helper.

## Naming conventions

- Suffix-per-role: `*Step` (flowstep steps), `*Service`/`*Enricher`
  (domain logic), `*Repository`, `*Client`, `*Mapper`, `*Agent`, `*Config`.
- Flow factory functions: `build_<domain>_<stage>_flow` (e.g.
  `build_knowledge_indexing_flow`, `build_quiz_cleaning_flow`).
- `UseCase`-implementing collaborators are stored on `self` named after
  what they *are* (e.g. `self._agent`), never `self._use_case` — see
  `feedback_usecase_naming` memory.
