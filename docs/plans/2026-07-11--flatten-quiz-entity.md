# Flatten Quiz Entity

References:
- `docs/database.md` (quiz_questions schema)
- `docs/architecture.md` (quiz bank pipeline)
- Memory: hybrid-search planning (paused) — retrieval strategy that will consume these columns

## Context and motivation

The `QuizQuestion` entity currently carries an opaque `quiz_metadata` object, persisted
as a `JSONB` blob in `quiz_questions`. The metadata is an LLM product (generated by the
`NormReferenceEnricher`) used as a retrieval bridge to `knowledge_chunks`. Burying it in
JSONB hides the role of each field and makes the retrieval keys neither queryable nor
indexable.

This plan flattens the entity: the retrieval-relevant metadata fields become first-class
`quiz_questions` columns, a DB-managed load timestamp is added, and `QuizMetadata` is
relocated to the ingestion layer as a transient LLM-output / embedder-input model (it is
no longer a persisted entity). The metadata stays a cohesive object throughout the
pipeline and flattens **only** at the entity boundary (the final mapper), so enrichers and
the embedding step are untouched.

### Affected areas

- `db/init.sql` — schema: new columns, drop `quiz_metadata` JSONB (requires DB recreate)
- `src/domain/entities/quiz/` — `quiz_question.py` flattened, `quiz_metadata.py` removed, `__init__.py`
- `src/guidami_ai_patente_ingestor/models/quiz/` — new home for `QuizMetadata`
- `src/guidami_ai_patente_ingestor/mappers/quiz_mapper.py` — `from_embeddable_to_quiz_question` spreads metadata onto the entity

### Success criteria

`quiz_questions` has columns `core_concepts TEXT[]`, `named_entities TEXT[]`,
`exact_keywords TEXT[]`, `rule_explanation TEXT`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`;
`quiz_metadata` JSONB removed. `QuizQuestion` is flat (no nested `QuizMetadata`).
`QuizMetadata` lives under `guidami_ai_patente_ingestor/models/quiz`, not `domain/entities`.
The repository inserts the new columns; enrichers and `EmbedQuizMetadata` are unchanged.
`uv run pytest` green; `ruff` and `pyright` clean.

## Non-goals

- Do NOT persist `image_description` (stays an ingestion intermediate).
- Do NOT persist `vector_search_queries` (embedder input only, not a retrieval key).
- Do NOT switch the write strategy to upsert: `created_at` is the load-batch timestamp,
  truncate + bulk-insert stays.
- **Do NOT re-run ingestion (`ingest prepare/index quiz`)** as part of this work —
  explicitly deferred until the user asks. The `docker compose down -v && up -d` schema
  recreate is documented here but is a manual operational step, not automated by this plan.
- Do NOT add FTS/GIN indexes or implement hybrid search now (schema prepared, indexes deferred).
- No unrelated refactoring.

## Decisions

1. **Which metadata fields become columns** — `core_concepts`, `entities`, `exact_keywords`
   (retrieval keys) → `TEXT[]`; `rule_explanation` (serving payload) → `TEXT`.
   `vector_search_queries` is the embedding **input** and is not persisted (retrieval uses
   the vector, not the raw text). It survives on disk in the parsed JSON if re-embedding is
   ever needed.
2. **Nullable columns** — all four metadata columns are nullable. Metadata is all-or-nothing
   (the LLM produces the whole object or none), so `NULL` means "no metadata generated",
   preserving the current signal (aligned with `embedding` being `NULL` on the same rows).
   Rejected `NOT NULL DEFAULT '{}'`: it erases the "metadata absent" distinction.
3. **`created_at` semantics** — DB-managed `TIMESTAMPTZ NOT NULL DEFAULT now()`, **not** in
   the INSERT column list, **not** on the entity. Under truncate + bulk-insert it is the
   load-batch timestamp, not "first ingestion". True first-ingestion would require upsert —
   out of scope (no read path exists today).
4. **`QuizMetadata` relocation** — moves from `domain/entities/quiz/` to
   `guidami_ai_patente_ingestor/models/quiz/`. It is no longer a persisted entity but a
   transient model (LLM output + embedder input). `embedded_text` stays on it. This aligns
   with the "entities mirror DB / non-persisted data lives on intermediate models" convention.
5. **Column naming** — the metadata field `entities` maps to column/field `named_entities`,
   to avoid semantic collision with the `entities/` domain package (it means "named entities
   mentioned in the question", not domain entities).
6. **Flatten point** — flattening happens only in `QuizMapper.from_embeddable_to_quiz_question`.
   `EmbeddableQuizModel` / `EnrichedQuizModel` keep the nested `QuizMetadata` (needed for
   `embedded_text`); only their import path changes.

## Open questions / Risks

- **DB recreate is destructive and manual.** `docker compose down -v` wipes the volume;
  both `knowledge_chunks` and `quiz_questions` are lost and must be re-ingested afterwards.
  This is deferred (non-goal) and must be run consciously by the user, not by this plan.
- **`created_at` is not first-ingestion.** Accepted trade-off (Decision 3). Revisit only if
  a real "question age" requirement emerges → would force upsert.
- **psycopg array adaptation.** `list[str]` adapts natively to Postgres `TEXT[]`; unlike the
  pgvector `%s::vector` case, no explicit cast is needed. Verified by the repository test.

## Implementation tasks

### 1. Schema — `db/init.sql`
In `CREATE TABLE quiz_questions`: remove `quiz_metadata JSONB`; add `core_concepts TEXT[]`,
`named_entities TEXT[]`, `exact_keywords TEXT[]`, `rule_explanation TEXT` (all nullable) and
`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`. Keep `embedding VECTOR(1536)`, `UNIQUE(number)`,
and the existing indexes unchanged. Add no new indexes.

**Tests** (intent, not contract): schema is validated by the integration repository test
(task 5) that inserts and reads back a `QuizQuestion` against a real DB; no separate SQL unit test.

### 2. Relocate `QuizMetadata` to ingestion models
Create `src/guidami_ai_patente_ingestor/models/quiz/quiz_metadata.py` with the `QuizMetadata`
model (fields + `embedded_text` property) verbatim. Add it to `models/quiz/__init__.py`
`__all__`. Delete `src/domain/entities/quiz/quiz_metadata.py` and remove `QuizMetadata` from
`src/domain/entities/quiz/__init__.py` (leaving only `QuizQuestion`).
Update all importers to `from guidami_ai_patente_ingestor.models.quiz import QuizMetadata`
(absolute across package boundary) except same-package files which use a relative import:
- `models/quiz/embeddable_quiz.py`, `models/quiz/enriched_quiz.py` → `from .quiz_metadata import QuizMetadata`
- `mappers/agents/norm_reference_describer_mapper.py` → absolute import

**Tests** (intent, not contract):
- Move `tests/domain/entities/quiz/test_quiz_metadata.py` → `tests/guidami_ai_patente_ingestor/models/quiz/test_quiz_metadata.py`, updating the import.
- Update imports in `tests/commons/services/embeddings/test_embedding_service.py`, `tests/guidami_ai_patente_ingestor/services/quiz/test_embed_quiz_metadata.py`, `tests/guidami_ai_patente_ingestor/models/quiz/test_embeddable_quiz.py`.

### 3. Flatten `QuizQuestion` entity
Rewrite `src/domain/entities/quiz/quiz_question.py`: drop the `quiz_metadata` field and its
import; add `core_concepts: list[str] | None = None`, `named_entities: list[str] | None = None`,
`exact_keywords: list[str] | None = None`, `rule_explanation: str | None = None`. Keep
`number, question_id, topic, text, correct_answer, image_filename, embedding`. No `created_at`
field (DB-managed).

**Tests** (intent, not contract):
- Add `tests/domain/entities/quiz/test_quiz_question.py::test_quiz_question_is_flat` — asserts `model_fields` contains the four flat fields and not `quiz_metadata`.

### 4. Update `QuizMapper.from_embeddable_to_quiz_question`
Spread the metadata explicitly (verbose, per mapper convention): read `model.quiz_metadata`;
if `None`, the four fields are `None`; otherwise map `core_concepts`, `entities → named_entities`,
`exact_keywords`, `rule_explanation`, dropping `vector_search_queries`. Keep `embedding` and
the existing plain fields. Remove the `base.model_copy(update={"quiz_metadata": ...})` step.

**Tests** (intent, not contract):
- Modify `tests/guidami_ai_patente_ingestor/mappers/test_quiz_mapper.py` — the `from_embeddable_to_quiz_question` cases assert flat fields (incl. `entities → named_entities`, `vector_search_queries` dropped) and the `quiz_metadata is None` case yields four `None` fields.

### 5. Update `QuizQuestionStoreRepository`
Replace `_QUIZ_QUESTION_TABLE_COLUMNS` with `number, question_id, topic, text, correct_answer,
image_filename, core_concepts, named_entities, exact_keywords, rule_explanation, embedding`
(no `created_at` — DB DEFAULT; no `quiz_metadata`). Rewrite `_to_db_row` to return the flat
tuple; drop the `Jsonb(...)` wrapping and its import. `list[str]` adapts to `TEXT[]` natively.

**Tests** (intent, not contract):
- Modify `tests/guidami_ai_patente_ingestor/repositories/test_quiz_question_store_repository.py` — assert the emitted row tuple/columns match the new flat set (and, if integration-marked, round-trips against a real DB).

### 6. ADR 0002 + second-brain docs update
Author `docs/adr/0002-flatten-quiz-metadata-columns.md` following `docs/adr/template.md`.
Scope it to the **one** architectural decision (not all six): quiz metadata is flattened
into first-class columns and `QuizMetadata` is demoted from a persisted entity to a transient
ingestion model. Alternatives considered: keep the opaque `quiz_metadata` JSONB blob; keep
`QuizMetadata` as a persisted entity. Consequences: retrieval keys become queryable/indexable;
`vector_search_queries` is not persisted (re-embedding relies on the parsed JSON on disk);
`created_at` is a load-batch timestamp, not first-ingestion (upsert knowingly deferred).
Decisions 2 (nullability), 4 (relocation as convention application), 5 (`named_entities`),
6 (flatten point) are routine and stay in the second-brain docs, not the ADR.

Then run the `second-brain:update` skill: update `docs/database.md` (quiz_questions columns:
