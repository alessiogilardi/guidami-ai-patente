# Quiz Enrichment: NormReference Keywords

References: `docs/architecture/modules/ingestor/quiz_pipelines.md`,
`docs/plans/2026-07-03--ingest-quiz-indexing-metadata-embedding.md` (dependent plan),
`docs/plans/2026-07-03--ingest-llm-as-judge.md`

## Context and motivation

The quiz enrichment phase currently produces `EnrichedQuizModel` with only `image_description`
(a visual description for quizzes with road signs). The future LLM-as-judge needs an additional
metadata field per sub-question:

**`quiz_metadata`** — a JSON structure containing normative concepts, entities, exact keywords,
semantic search queries, and a rule explanation, generated by an LLM. It serves as a
**retrieval bridge** toward `knowledge_chunks`: the judge reads the metadata and performs
targeted lookups instead of a blind similarity search from quiz to norms.

The field is **persisted in the DB**. Embedding computation from `quiz_metadata` is delegated
to the separate indexing plan (`2026-07-03--ingest-quiz-indexing-metadata-embedding.md`),
which replaces the content of `embedded_text` with `vector_search_queries`.

## Non-goals

- Embedding computation from `quiz_metadata` — handled entirely in the dependent indexing plan
- Changes to `ImageDescriptionEnricher` or the image description enrichment step
- Changes to knowledge corpus ingestion pipelines (`knowledge_chunks`)
- LLM-as-judge integration — separate plan (`2026-07-03--ingest-llm-as-judge.md`)
- Retrieval or querying logic (read path) — this plan covers only the write/ingestion path

## Decisions

1. **Dedup key `(topic, text, correct_answer, image_filename)`** — sub-questions with the same
   combination get one LLM call; the result is propagated to all matching rows. `correct_answer`
   is included because the prompt yields different output for True/False answers.
   `image_filename` is used (not `image_description`) because it is a static, deterministic
   value. The key is computed by the enricher directly from `EnrichedQuizModel` via `_make_key`;
   it is not part of the request DTO.

2. **`quiz_metadata` as JSONB** — a JSON object with fields `core_concepts`, `entities`,
   `exact_keywords`, `vector_search_queries`, `rule_explanation`. Enables structured lookup
   by the judge without full-text scan.

3. **Text-only agent pattern** — same structure as `RoadSignDescriberAgent` but without images:
   `run_sync(request, images=())`. Config in YAML, separate request/response DTOs.

4. **`embedded_text` managed in the indexing plan** — `EmbeddableQuizModel.embedded_text` will
   delegate to `quiz_metadata.embedded_text` in the indexing phase; its current content
   (quiz text) is removed in that plan. See `2026-07-03--ingest-quiz-indexing-metadata-embedding.md`.

5. **JSONB serialization** — in `_to_db_row`, wrap with `psycopg.types.json.Jsonb(...)`
   calling `item.quiz_metadata.model_dump()` to avoid type ambiguity with psycopg3.

6. **`image_filename` excluded from request DTO** — the request carries only prompt-relevant
   fields (`topic`, `text`, `correct_answer`, `image_description`). `image_filename` stays on
   `EnrichedQuizModel` and is read by the enricher for the dedup key via `_make_key`.

7. **`QuizMetadata` as domain model in `commons`** — typed as `QuizMetadata | None` on all
   pipeline models and the entity. Lives in `commons` because it is a shared domain concept
   between ingestor and future judge (Clean Architecture: dependencies point inward).
   `NormReferenceDescriberResponse` is a separate DTO with the same shape: the duplication is
   intentional because the two objects have independent lifecycles (agent DTO vs. domain model).

### 7. Enricher: NormReferenceEnricher

Create **`src/guidami_ai_patente_ingestor/services/quiz/enrichers/norm_reference_enricher.py`**:

```python
class NormReferenceEnricher(UseCase[list[EnrichedQuizModel], list[EnrichedQuizModel]]):
    def __init__(self, agent: NormReferenceDescriberAgent) -> None: ...
    def execute(self, request: list[EnrichedQuizModel]) -> list[EnrichedQuizModel]: ...
```

Dedup key: `_make_key(q: EnrichedQuizModel) -> tuple` returns
`(q.topic, q.text, q.correct_answer, q.image_filename)`.

Same pattern as `ImageDescriptionEnricher` but:
- No check for an image file on disk
- Calls `agent.run_sync(request, images=())` (text-only)
- On error: skip + warning log; `quiz_metadata` remains `None`
