# Remove Quiz Named Entities

References:
- `docs/adr/0002-flatten-quiz-metadata-columns.md` — flattened `named_entities` onto `quiz_questions`; this plan removes that column.
- `docs/database.md` — `quiz_questions` schema (to update).
- `.claude/rules/code-conventions.md` — Language section (to extend with the prompt-facing exception).

## Context and motivation

The 'entities' field generated by the LLM in NormReferenceEnricher and persisted as quiz_questions.named_entities is redundant with core_concepts/exact_keywords, semantically defined by subtraction (fuzzy boundaries, vague prompt), does not contribute to the embedding, and has no downstream reader. Removing it end-to-end eliminates one LLM output slot per call and a dead DB column.

The field travels through the whole quiz enrichment chain as a symmetric per-layer field:
`prompt → NormReferenceDescriberResponse.entities → QuizMetadata.entities →
NormReferenceDescriberMapper → QuizMapper (renamed to named_entities) →
QuizQuestion.named_entities → QuizQuestionStoreRepository → quiz_questions.named_entities`.
It never contributes to the embedding (`QuizMetadata.embedded_text` uses only
`vector_search_queries`) and no code reads `named_entities` back — the only consumers are
the `INSERT` write path and the review viewer's rendering.

**Broadened scope — prompt redefinition.** Because the `norm_reference_describer` prompt
must be edited anyway to drop `entities`, a prompt-engineering review was run and surfaced
structural defects the plan also fixes (each is a self-contained change, not open-ended
prompt tuning):

1. **Duplicated output contract.** `BaseAgent` builds `pydantic_ai.Agent(output_type=NormReferenceDescriberResponse)`,
   so pydantic-ai already ships the model's JSON schema (field names, descriptions,
   `min/max_length`) to the LLM. The YAML prompt *also* hand-writes the JSON schema
   (lines 20-27), in a different language and with divergent constraints — two sources of
   truth that drift. Collapsing to one (the Pydantic schema) makes future contract edits a
   single-file change.
2. **`rule_explanation` hard char cap triggers retries.** `max_length=250` on an
   LLM-generated field raises `ValidationError` on overflow, which under `retries` re-runs
   the whole call — a slightly-too-long answer wastes an LLM call instead of being accepted.
3. **`$image_description` renders `None`.** `PromptRenderer` uses `Template.safe_substitute`
   over `request.model_dump()`; for text-only questions `image_description=None` renders the
   literal token `None` into the prompt.
4. **No few-shot.** The subtle distinctions between the remaining fields are only described
   abstractly; one concrete example stabilizes them far better on a small model (Flash-Lite).

### Affected areas

NormReferenceDescriberResponse (DTO), all agent response DTOs under `src/guidami_ai_patente_ingestor/agents/dto/*/*_response.py` (ArticleContextualizerResponse, RoadSignDescriberResponse), configs/agents/norm_reference_describer.yaml prompt, NormReferenceDescriberMapper, QuizMetadata, QuizMapper, QuizQuestion entity, QuizQuestionStoreRepository, db/init.sql, quiz-enrichment-review.html viewer, related tests, `.claude/rules/code-conventions.md`, Second Brain docs (database.md).

### Success criteria

grep over src and tests finds no reference to the removed quiz field (`entities`/`named_entities`); the YAML prompt no longer hand-writes the JSON schema; `uv run pytest`, `ruff` and `pyright` green; DB volume recreated from updated schema without the column.

## Non-goals

- No re-run of the ingestion pipeline (`prepare`/`index quiz`).
- No changes to the semantics of the four remaining metadata fields (their mutual overlap, e.g. `core_concepts` vs `exact_keywords`, is out of scope).
- No new retrieval/hybrid-search logic.
- No changes to the generic `PromptRenderer` (the `$image_description` fix is local to the mapper).

## Decisions

1. **Approach A — end-to-end vertical deletion of `entities`** — Remove the field from every layer in one coherent slice. Rejected: (B) stop generating it but keep the DB column — leaves the dead column that motivates the work; (C) gradual deprecation — YAGNI, no downstream consumer to migrate.
2. **No DB migration; recreate the volume** — `db/init.sql` is the schema source of truth and the project recreates the Postgres volume (`down -v` + `up`) rather than running ALTER migrations. Consistent with CLAUDE.md "Recreate DB from scratch".
3. **No pipeline re-run in scope** — After `down -v` the `quiz_questions` table is empty; repopulating it (`ingest prepare/index quiz`) is a user-run follow-up, explicitly out of scope.
4. **ADR 0002 is not rewritten** — ADRs are an immutable historical record. The removal is reflected in `database.md`; a short superseding note is left to the `second-brain:update` skill.
5. **Single output contract = the Pydantic schema** — Delete the hand-written JSON schema block from the YAML prompt; `output_type=NormReferenceDescriberResponse` is the single source of truth pydantic-ai ships to the model. The prompt keeps role, task, guardrail, and one few-shot example. Rejected: keeping a minimal per-field reminder — still a second contract to maintain.
6. **Prompt-facing text on response models is Italian** — A response model's class docstring and `Field(description=...)` are shipped to the LLM by pydantic-ai (docstring → output/tool description, descriptions → field schema); they are functionally *prompt content*, not code documentation. The domain is Italian legal text (CdS/CAP) and the system prompts are already Italian, so Italian descriptions improve extraction fidelity and remove the current IT/EN split. This is a deliberate, narrow exception to the project's "English only" rule (`code-conventions.md`), documented both inline in the DTOs and in the rule file. **Scope of the exception**: it applies to **every agent response DTO** under `agents/dto/*/*_response.py` (the text pydantic-ai transmits to the model — class docstring + field descriptions), for cross-agent consistency. It does **not** apply to request DTOs (`*_request.py`): their values are substituted into the user-prompt template, but their docstrings/descriptions are never shipped to the model as schema, so they stay English. All other docstrings/comments/logs stay English.
7. **`rule_explanation` cap becomes a loose safety net** — Raise `max_length` to 500 (tunable) as a runaway-hallucination guard only; the "~30 words, concise and technical" guidance moves to soft wording in the description. Rejected: removing the cap entirely — keeps no guard against pathological output; keeping 250 — trips on normal variation and burns a retry.
8. **`$image_description` None handled in the mapper** — `NormReferenceDescriberMapper.from_enriched_quiz_to_request` coerces `image_description=None` to the explicit Italian sentinel `"Nessuna immagine allegata a questa domanda."`. This both fixes the `None` token and gives the model a positive "no image" signal, without adding conditional logic to the generic `PromptRenderer`.
9. **Add field descriptions where response DTOs lack them** — `ArticleContextualizerResponse` and `RoadSignDescriberResponse` currently have no `Field(description=...)`. Add Italian descriptions giving the model an explicit per-field contract (e.g. the `comma_index → context` key semantics of `contexts`; the Chain-of-Thought role of `visual_analysis`). The CoT field-order note on `RoadSignDescriberResponse` is behavioral and must be preserved when translating its docstring.

## Open questions / Risks

- **Prompt quality drift**: dropping `entities` and restructuring the prompt could marginally shift how the model populates the remaining four fields. Low risk, no re-run in scope, so no immediate observable impact — validated at the eventual re-ingestion.
- **Few-shot vs single-contract tension**: the few-shot example is JSON and names the fields, partially echoing the schema. Mitigated by keeping it strictly *illustrative* (a filled example), not a normative per-field spec — the schema stays the only contract.
- **Positional column/value alignment** in `QuizQuestionStoreRepository`: `_QUIZ_QUESTION_TABLE_COLUMNS` and `_to_db_row` must stay aligned after removal. Covered by `test_table_columns...` and `test_to_db_row...`.
